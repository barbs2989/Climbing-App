- **SINGLE** — one practical way in; the flag was a second card from the same trailhead, a seasonal
  snow line, a gate, or a landmark read as a trailhead. No change.
- **MULTI_TRAILHEAD** — two or more ways in from DIFFERENT trailheads that parties choose between.
  Each becomes an `approach_variants` entry with a `trip` (trailhead + numbers + optional GPX), and
  the route page's picker switches between them. Only 37 have a trailhead coordinate for two or
  more ways in, and per-way-in distance/gain is mostly unpublished — **coordinates were never
  guessed**; a null is a research gap, and climbers can now fill it from the edit sheet.
- **FINISH** — reached by other catalog routes on the same peak; link with `viaRouteId` like Shuksan.
- **ROW_CONTRADICTS** — the row's own fields disagree about which trailhead it uses. Owner decisions
  before any linking (`docs/codebase/route-identity.md` rules apply).

Per-route records — each way in's camps, join point and when to choose it, plus the research links
(which never reach the app): `2026-10-01-research.json`.
